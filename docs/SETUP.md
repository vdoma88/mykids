# Установка: с нуля до работающего

Нужны: одна машина под сервер (подойдёт домашний мини-ПК, NAS или тот же
компьютер родителя) и компьютер ребёнка под Windows 10 или 11.

Весь порядок — примерно на полчаса, из них двадцать минут уйдёт на
обдумывание лимитов и курса обмена.

---

## 1. Сервер

Данные об активности ребёнка не уходят в чужое облако: всё остаётся дома.
Командная строка не нужна ни в одном из двух вариантов — выберите тот, на
чём сервер будет жить.

### Вариант А: обычный компьютер с Windows

Со [страницы релиза](https://github.com/vdoma88/mykids/releases/latest)
скачайте **`MyKids-Server-Setup-X.Y.Z.exe`** и запустите. Ничего настраивать
не нужно: Node.js и база PostgreSQL уже внутри, база заведётся сама, пароль к
ней придумается сам, а порт откроется в брандмауэре только для домашней сети.

В конце мастер покажет два адреса:

- **админка на этом компьютере** — `http://localhost:3000`;
- **с других устройств дома** — например `http://192.168.1.10:3000`. Его
  вы впишете в установщик на компьютере ребёнка.

Эти же адреса всегда показывает **«MyKids Сервер»** в меню «Пуск» — там же
кнопки «Открыть админку», «Скопировать адрес для ребёнка», «Сделать резервную
копию», «Восстановить из копии», «Сменить порт» и «Журналы». Резервная копия
делается и сама, раз в сутки; хранятся последние семь.

Компьютер должен быть включён, когда ребёнок пользуется своим. Если он
выключен, компьютер ребёнка копит учёт у себя и отправит, когда связь
вернётся; задания и магазин в это время недоступны.

### Вариант Б: NAS или любая машина с Docker

Synology, QNAP, TrueNAS, Unraid, Portainer — у всех есть окно, куда
вставляется файл `docker-compose.yml`. Возьмите
[`deploy/nas/docker-compose.yml`](https://github.com/vdoma88/mykids/blob/main/deploy/nas/docker-compose.yml)
и вставьте целиком, ничего не правя:

| NAS | Где |
|---|---|
| Synology | Container Manager → Проект → Создать → «Создать docker-compose.yml» |
| QNAP | Container Station → Приложения → Создать |
| Portainer | Stacks → Add stack → Web editor |
| TrueNAS | Apps → Discover → Install via YAML |

Готовый образ скачается сам — собирать ничего не нужно. Пароля базы в файле
нет намеренно: база живёт во внутренней сети Docker, куда нет хода ни из
дома, ни из интернета, — только серверу MyKids. Если порт 3000 на NAS занят,
поменяйте левое число в строке `"3000:3000"`.

Откройте `http://адрес-NAS:3000/` — должна открыться страница входа.

<details>
<summary>Из исходников, если вы разработчик</summary>

```bash
git clone https://github.com/vdoma88/mykids.git
cd mykids
docker compose -f deploy/docker-compose.yml up -d --build
```

`deploy/.env` не обязателен. Установки до 0.9.1 заводили базу с паролем из
него: оставьте файл на месте, и всё будет работать как раньше.
</details>

> Сервер доступен по HTTP, без шифрования. В домашней сети этого достаточно.
> Выставлять его в интернет **не нужно**: агенту хватает локальной сети,
> а токен устройства по открытому каналу через интернет ходить не должен.

## 2. Семья, ребёнок, правила

В открывшейся админке:

1. **Зарегистрируйтесь.** Первый аккаунт становится владельцем семьи.
   Сразу включите второй фактор — пароль от админки это пароль от экранного
   времени, и подобрать его ребёнок попробует.
2. **Заведите ребёнка** и задайте политику: дневной лимит по дням недели,
   перенос остатка, окна расписания (школа, отбой), курс обмена кредитов в
   минуты и потолки.
3. **Назначьте пакеты заданий** — то, чем ребёнок будет зарабатывать. Без
   этого шага заработать кредиты ему негде, и остаётся только просить у вас.

Курс обмена сразу «на глаз» не выставляется. На странице ребёнка есть
симулятор: он считает теми же функциями, что и сервер, и показывает, во что
превращается дневной заработок. Посмотрите на цифру, прежде чем соглашаться.

## 3. Учётная запись ребёнка на его компьютере

**Единственное условие, без которого всё остальное бессмысленно:** учётная
запись ребёнка должна быть обычной, без прав администратора. Ребёнок с правами
администратора останавливает службу из оснастки, и агент не помешает ему ничем.

Проверить: «Параметры» → «Учётные записи» → «Семья и другие пользователи».
Под именем ребёнка должно быть написано «Обычный доступ», а не
«Администратор». Если написано «Администратор» — «Изменить тип учётной
записи» → «Обычный пользователь».

Родительская учётная запись при этом остаётся администратором: из неё вы
ставите агент и правите настройки.

## 4. Агент на компьютере ребёнка

В админке, на странице ребёнка, нажмите **«Выдать токен»** — он показывается
один раз, поэтому держите страницу открытой, пока не закончите.

Со [страницы релиза](https://github.com/vdoma88/mykids/releases) скачайте
**`MyKids-Setup-X.Y.Z.exe`** и из учётной записи **родителя** запустите
двойным щелчком. Windows спросит разрешение на изменения — служба ставится на
всю машину. Подпись кода пока не куплена, поэтому SmartScreen может
предупредить о неизвестном издателе: «Подробнее» → «Выполнить в любом случае».
Сверить файл можно по `sha256.txt` из того же релиза:
`certutil -hashfile MyKids-Setup-X.Y.Z.exe SHA256`.

Мастер спросит три вещи:

| Поле | Что вписать |
|---|---|
| Адрес сервера | тот, по которому вы открываете админку |
| Токен устройства | тот, что только что выдали |
| Учётная запись ребёнка | выберите из списка — там только обычные учётные записи этого компьютера |

**Адрес должен быть сетевым, а не `localhost`.** Свой сервер вы, скорее всего,
открываете как `http://localhost:3000` — но здесь, на компьютере ребёнка, это
означает сам компьютер ребёнка. Нужен адрес в домашней сети, например
`http://192.168.1.10:3000`. Мастер это проверяет и не даст ошибиться.

Прежде чем что-то менять, мастер **спросит сервер, чей это токен**, и покажет:
«это будет компьютер ребёнка „Маша“». Так сразу видно и опечатку в адресе, и
отозванный токен, и токен, выданный не тому ребёнку, — раньше всё это
обнаруживалось только через день, когда в админке не появлялось минут. Заодно
он проверит, что учётная запись ребёнка не администратор.

Дальше всё сам: программы — в `C:\Program Files\MyKids`, каталог данных — в
`C:\ProgramData\MyKids` с доступом только для службы и администраторов,
привязка, служба с автозапуском. Запустилась ли она, мастер дождётся и скажет.
Ещё он заведёт:

- в меню «Пуск» → MyKids: «Проверка MyKids», «Задания и магазин», «Удалить MyKids»;
- на общем рабочем столе — ярлык **«Задания MyKids»**: ребёнок увидит его в
  своей учётной записи и найдёт задания, не дожидаясь закрытого экрана;
- запись в «Программах и компонентах».

Всё, что происходит, видно в окне мастера и пишется в `%TEMP%\mykids-setup.log`.

<details>
<summary>Без окон: на несколько машин или из скрипта</summary>

```powershell
.\MyKids-Setup-X.Y.Z.exe /S /SERVER=http://192.168.1.10:3000 /TOKEN=<токен> /CHILD=<учётная запись>
```

Проверки те же, что в мастере. Код возврата: `0` — готово, `1` — не прошла
проверка или привязка (причина в `%TEMP%\mykids-setup.log`), `4` — на машине
уже стоит более новая версия. Токен у каждого компьютера свой: выдайте по
одному на устройство.
</details>

Каталог данных — машинный, а не в профиле, и это не мелочь: служба работает
под `LocalSystem`, а привязку делаете вы из своей учётной записи. В профилях
это были бы два разных каталога, и служба молча работала бы автономно.

## 5. Проверка

**Войдите в учётную запись ребёнка** и запустите «Проверка MyKids» из меню
«Пуск». Командная строка не нужна: откроется окно с четырьмя кнопками.

1. **«Проверить всё»** — уберите руки от мыши на несколько секунд. Программа
   спросит у Windows ровно то же, что спрашивает агент: активное окно, время
   простоя, состояние экрана, встречную проверку экрана через диспетчер
   сессий, номер сессии, состояние службы. Каждая строка сама говорит, хорошо
   это или плохо и что делать, если плохо.
2. **«Показать предупреждение»** и **«Закрыть экран на 5 секунд»** — то, что
   увидит ребёнок. Экран откроется сам; программа спросит, видели ли вы его.
3. **«Скопировать отчёт»** — отчёт уходит в буфер обмена. Он же пишется в
   `%TEMP%\mykids-check.log`.

Запускать её нужно именно из учётной записи ребёнка: проверяется то, что
увидит он. Из учётной записи администратора программа об этом предупредит.

Связь с сервером видно из учётной записи родителя: **«Панель MyKids»** в меню
«Пуск» покажет, работает ли служба, отвечает ли сервер, чей это компьютер и
сколько у ребёнка осталось минут и кредитов. Там же — «Привязать» (новый токен
или новый адрес сервера) и «Перезапустить службу».

Помощника служба поднимает сама — запускать руками ничего не надо. За
несколько минут до конца лимита внизу справа появится полоса «Осталось N минут
· Сохранись», а когда время кончится — экран закроется с объяснением, сколько
есть кредитов и где задания.

В админке, на странице ребёнка, к этому времени появятся израсходованные
минуты.

## Что ребёнок может, а что нет

Честно, без обещаний:

| Попытка | Что будет |
|---|---|
| Закрыть помощника | Служба поднимет его обратно; молчание помощника считается расходом, а не отдыхом |
| Снимать помощника раз за разом | Пять раз за десять минут — и родителю уходит событие |
| Остановить службу из своей учётки | Не хватит прав |
| Убить агент целиком (с правами администратора) | Пропущенное время спишется при следующем запуске, родитель получит событие |
| Перевести системные часы | Сдвиг замечается и гасится поправкой, родитель получает событие |
| Править `policy.json` | Ничего не даст: правила берутся из кэша, полученного с сервера |
| Подменить помощника своим | Ложь о простое ловится на противоречии: без ввода активное окно не меняется |
| Удалить каталог данных | Нет прав; а пропуск всё равно оплачивается при следующем запуске |

Чего агент **не** умеет: он не помешает ребёнку с правами администратора, не
работает на втором компьютере без второй привязки и не следит за тем, что
именно ребёнок делает на экране — только за тем, какое окно активно и сколько
времени прошло.

## Задания с закрытого экрана

Когда время кончилось, экран закрыт целиком, включая браузер. Задания в этот
момент открываются с другого устройства — с телефона или планшета, по тому же
адресу `/child`.

Открыть их на самом заблокированном компьютере можно, добавив браузер в
`alwaysAllowed` в политике, но надо понимать цену: браузер, внесённый в белый
список, не блокируется и не считается **никогда**, то есть ребёнок получает
неограниченный интернет. Это ваш выбор, и по умолчанию он не сделан за вас.
Задания и магазин в отдельном окне агента — в планах (`docs/ROADMAP.md`).

## Обновление и удаление

**Обновление** — новый `MyKids-Setup-X.Y.Z.exe` поверх старого. Привязка
сохраняется: токен заново не нужен, достаточно нажать «Далее». Если сервер
переехал на другой адрес, а устройство в админке не отвязывали, впишите новый
адрес и оставьте токен пустым — мастер проверит прежний токен на новом адресе.
Учёт прервётся на минуту, пока служба перезапускается.

Версии до 0.9 ставились пакетом `mykids.msi` или окном `mykids-setup.exe`.
Новый установщик ставится поверх любой из них: пакет MSI удалит сам, чтобы в
«Программах и компонентах» не было двух записей, а привязку подхватит.

**Удаление** — «Параметры» → «Приложения» → MyKids, или «Удалить MyKids» в
меню «Пуск». Деинсталлятор снимает службу и закрывает помощника в сессии
ребёнка: без службы помощник через минуту закрыл бы экран, и ребёнок остался
бы перед ним до перезагрузки.

Каталог `C:\ProgramData\MyKids` по умолчанию **остаётся** — в нём привязка и
ещё не отправленный учёт. Удалить и его можно галочкой «Журнал учёта и
привязка» в деинсталляторе (без окон — `uninstall.exe /S /PURGE`). После
удаления отвяжите устройство в админке, во вкладке «Устройства».

Сервер остаётся в любом случае: журнал и балансы никуда не денутся.

### Обновление сервера

- **Windows:** новый `MyKids-Server-Setup-X.Y.Z.exe` поверх старого. База,
  семья и резервные копии сохранятся; изменения базы применятся сами.
- **NAS:** в интерфейсе контейнеров — «Обновить образ» / «Pull and redeploy»
  для проекта mykids. Данные лежат в томе и переживают обновление.

<details>
<summary>Из исходников</summary>

```bash
cd mykids
git pull
docker compose -f deploy/docker-compose.yml up -d --build
```

`--build` обязателен: без него compose перезапустит старый образ.
</details>

## Если что-то не работает

| Симптом | Где смотреть |
|---|---|
| Админка не открывается | Windows: «MyKids Сервер» в «Пуске» → «Обновить», затем «Журналы». NAS: журнал контейнера mykids-server в интерфейсе NAS |
| Компьютер ребёнка не видит сервер | «MyKids Сервер» → «Скопировать адрес для ребёнка» и сверьте с тем, что вписано в «Панели MyKids» |
| Панель говорит «нет связи с сервером» | Её сообщение называет причину: адрес, токен или брандмауэр |
| Минуты не доходят до сервера | Учёт копится у агента и уйдёт сам, когда связь вернётся |
| Экран не закрывается | Проверьте, что ребёнок вошёл в свою учётную запись, а не в родительскую |
| Служба на компьютере ребёнка не стартует | «Панель MyKids» → «Перезапустить службу»; подробности — «Скопировать отчёт» |
| Непонятно, видит ли агент экран | «Проверка MyKids» из меню «Пуск», из учётной записи ребёнка |
| Мастер не принимает адрес или токен | Его сообщение называет причину; подробности — `%TEMP%\mykids-setup.log` |
