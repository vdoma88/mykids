# MyKids Agent — Windows

Учёт и ограничение экранного времени на компьютере ребёнка.

**Статус: v0.** Ядро покрыто тестами и проверено, Win32-часть собрана, но
**не запускалась на Windows** — у меня не было такой машины. Поэтому в агенте
три режима, чтобы вы могли проверять его постепенно, а не сразу доверять ему экран.

## Проверка по шагам

```
mykids-agent.exe status    что агент видит прямо сейчас — один замер
mykids-agent.exe watch     учёт времени без блокировки
mykids-agent.exe run       учёт с блокировкой экрана
```

Начните со `status`. Он должен показать активное окно и остаток времени. Если
показывает — переходите к `watch` на день, и только потом к `run`.

## Привязка к серверу

```
mykids-agent.exe enroll -server https://адрес -token <токен устройства>
```

Токен выдаёт админка на странице ребёнка, кнопкой «Выдать токен», и показывает
его один раз. Без привязки агент работает автономно, по локальному файлу правил.

После привязки `status` показывает блок «связь с сервером»: прошёл ли обмен,
откуда взята политика, сколько минут ждёт отправки и есть ли поправка к часам.

## Файлы в `%APPDATA%\MyKids`

| Файл | Что в нём |
|---|---|
| `policy.json` | Локальные правила. Запасной вариант: применяются, только пока сервер не увидели ни разу |
| `policy-cache.json` | Правила, полученные с сервера. Именно по ним агент работает, в том числе без связи |
| `enrollment.json` | Адрес сервера и токен устройства |
| `state.json` | Расход за сегодня и вчера, поправка к часам, счётчики |
| `outbox.jsonl` | Израсходованные минуты, ещё не принятые сервером |

Правка `policy.json` после привязки ничего не даёт: агент берёт правила из кэша,
а он приходит с сервера. Это не случайность, а смысл разделения — файл лежит в
профиле ребёнка и доступен ему на запись.

## Почему Go, а не C#

В `docs/ARCHITECTURE.md` для Windows-агента выбран C#/.NET. На практике взят Go:

- **Один статический .exe без установки рантайма.** Для домашнего сценария это
  весомо: не нужно ставить .NET на компьютер ребёнка.
- Кросс-сборка из Linux одной командой, поэтому агент собирается в CI.
- `golang.org/x/sys/windows` покрывает нужные вызовы Win32 напрямую.

Минус — слабый GUI: оверлей написан на голых вызовах user32, а не на готовом
тулките. Для одного полноэкранного окна это приемлемо.

## Что уже делает

- Считает активное окно и простой; время без ввода не списывается
- Не считает и не блокирует приложения из белого списка
- Дневной лимит по дням недели, перенос остатка с потолком
- Окна расписания, в том числе через полночь
- Блокировка полноэкранным окном поверх всего, с откатом на `LockWorkStation`
- Атомарная запись состояния и счётчик нештатных остановок

- Обмен с сервером раз в минуту: правила оттуда, расход туда
- Очередь расхода переживает офлайн и перезапуск; повторная отправка не удваивает списание
- Ловит перевод системных часов и гасит его поправкой, сообщая родителю

## Чего пока нет

Службы Windows, трея, WebView с заданиями, защиты от снятия. Ребёнок с правами
администратора закроет агент из диспетчера задач — **учётная запись ребёнка
обязана быть обычной, без прав администратора**.

## Разработка

```bash
go test ./...                                   # тесты идут на любой ОС
GOOS=windows GOARCH=amd64 go build ./...        # проверка сборки под Windows
./build.sh                                      # dist/mykids-agent.exe
./integration.sh                                # прогон против живого API
```

`integration.sh` поднимает настоящий сервер на временной базе и гоняет клиента
против него. Юнит-тесты клиента ходят на фальшивый сервер, чьи ответы написаны
рядом с ними, и потому не поймают расхождения схем — этот прогон ловит.

Логика окон расписания намеренно повторяет `packages/domain/src/time.ts`: сервер
считает онлайн, агент обязан уметь офлайн. Обе реализации гоняют общий файл
`packages/contracts/test-vectors/schedule.json`, чтобы не разъехаться.
