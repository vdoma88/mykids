# Формат пакетов заданий (Task Pack)

Модульная система контента. Главное правило:

> **Типы заданий — это код. Сами задания — это данные.**
> Добавление нового предмета, темы или теста не требует пересборки и переустановки агентов.

---

## 1. Структура пакета

```
content/packs/<pack-id>/
├── pack.json          # манифест: метаданные + правила начисления
├── items/
│   ├── 001.json
│   ├── 002.json
│   └── …
├── assets/            # картинки, аудио — опционально
└── pack.sig           # подпись Ed25519, создаётся при публикации
```

Пакет распространяется как каталог (в репозитории) или как zip (`.mkpack`) при загрузке
через админку.

---

## 2. Манифест `pack.json`

```json
{
  "id": "ru.mykids.physics.mechanics.basic",
  "schemaVersion": 1,
  "version": "1.0.0",
  "title": "Механика: базовый уровень",
  "description": "Второй закон Ньютона, равномерное движение, плотность.",
  "subject": "physics",
  "gradeRange": [11, 13],
  "locale": "ru-RU",
  "author": "MyKids",
  "license": "CC-BY-4.0",
  "tags": ["физика", "механика", "7 класс"],
  "reward": {
    "creditsPerCorrect": 2,
    "bonusOnPerfect": 5,
    "dailyCreditCap": 40,
    "penaltyPerWrong": 0
  },
  "delivery": {
    "itemsPerSession": 8,
    "selection": "random",
    "passThreshold": 0.7,
    "cooldownHoursPerItem": 24,
    "timeLimitSec": 600
  },
  "items": ["items/001.json", "items/002.json"]
}
```

### Поля `reward` — экономика пакета

| Поле | Смысл |
|---|---|
| `creditsPerCorrect` | Базовое начисление за верный ответ |
| `bonusOnPerfect` | Бонус за 100% сессии |
| `dailyCreditCap` | **Потолок кредитов с этого пакета в сутки.** Обязателен — иначе фарм |
| `penaltyPerWrong` | Штраф за неверный ответ. По умолчанию 0 |

Итоговое начисление всегда проходит ещё и через глобальные лимиты ребёнка из Policy.
Пакет не может выдать больше, чем разрешает политика семьи.

### Поля `delivery` — как показывать

`selection`:
- `random` — случайные `itemsPerSession` из банка
- `sequential` — по порядку, с сохранением позиции
- `adaptive` — по сложности, с учётом истории (фаза 5)
- `spaced` — интервальное повторение (FSRS), кредиты за повтор убывают

`cooldownHoursPerItem` — одно и то же задание не приносит кредиты повторно раньше этого
срока. Ключевая антифарм-мера.

## 3. Типы заданий

Каждый тип — отдельный рендерер в `packages/task-runner`. Добавление типа — единственный
случай, когда нужен релиз кода.

### Оцениваемые (правильно/неправильно)

| `type` | Назначение |
|---|---|
| `single_choice` | Один вариант из нескольких |
| `multi_choice` | Несколько верных вариантов, частичный зачёт опционален |
| `numeric` | Числовой ответ **с единицами измерения и допуском** — для физики, химии, математики |
| `short_text` | Короткий текст, сверка по списку принятых вариантов или regex |
| `ordering` | Расставить в правильном порядке |
| `matching` | Сопоставить пары |
| `cloze` | Заполнить пропуски в тексте |
| `code` | Задача на программирование, проверка тестами в песочнице (фаза 5) |

### Неоцениваемые — для психологии и рефлексии

Психологическую практику нельзя оценивать «верно/неверно». Для неё отдельные типы,
которые начисляют кредиты **за выполнение**, а не за правильность:

| `type` | Назначение |
|---|---|
| `likert` | Шкала согласия. Даёт профиль, а не оценку |
| `reflection` | Свободный текст-рефлексия. Кредиты за содержательный ответ (минимум символов) |
| `parent_verified` | Задание в реальном мире. Кредиты после подтверждения родителем в админке |
| `interactive` | Собственный HTML/JS-виджет в песочнице: таблица Шульте, матрица Эйзенхауэра, дыхание 4-7-8 |

`parent_verified` — важный тип. Он позволяет завести в систему «убрал комнату»,
«прочитал главу», «отжался 20 раз» без всякой автоматики, и связывает экранное время
с офлайн-жизнью.

### `interactive` — как переносится существующий контент UKids

Все 12 недель программы уже перенесены из `legacy/ukids-app.html` конвертером
`packages/content-tools/bin/import-ukids.js` (`npm run import:ukids`). Упражнения — таблица
Шульте, матрица Эйзенхауэра, дыхание, «факт или мнение», игра на память, конструктор SMART,
ментальная карта — стали `interactive`-заданиями.

Пакеты в `content/packs/ru.mykids.psychology.*` **генерируются**: править их руками нельзя,
следующий импорт затрёт правки, и CI на это ругается. Менять нужно источник или конвертер.

Каждый виджет — самостоятельный модуль, который получает `props` из item и возвращает
результат:

```ts
export interface InteractiveWidget {
  mount(el: HTMLElement, props: unknown, prior?: unknown): void;
  getResult(): { completed: boolean; score?: number; data: unknown };
  unmount(): void;
}
```

Виджет исполняется в `<iframe sandbox>` без доступа к API баланса. Он может сообщить
«выполнено», но не может сам начислить кредиты — начисление всегда на сервере.

## 4. Примеры заданий

### `numeric` — физика

```json
{
  "id": "phys-mech-014",
  "type": "numeric",
  "difficulty": 2,
  "stem": "Тело массой 2 кг движется с ускорением 3 м/с². Найдите равнодействующую силу.",
  "answer": { "value": 6, "unit": "Н", "tolerance": 0.01, "acceptedUnits": ["Н", "N"] },
  "hints": ["Второй закон Ньютона: F = m·a"],
  "solution": "F = m·a = 2 кг · 3 м/с² = 6 Н",
  "credits": 2,
  "topics": ["второй закон Ньютона"]
}
```

`tolerance` и `acceptedUnits` — принципиальны. Без них любое задание с дробным ответом
превращается в лотерею на округлении, а ребёнок теряет мотивацию.

### `likert` — психология

```json
{
  "id": "psy-emotions-003",
  "type": "likert",
  "stem": "Мне легко назвать словами, что я сейчас чувствую.",
  "scale": { "min": 1, "max": 5, "minLabel": "Совсем не про меня", "maxLabel": "Точно про меня" },
  "dimension": "emotional_awareness",
  "credits": 1
}
```

Нет поля `answer` — правильного ответа не существует. Результаты собираются в профиль,
который родитель видит как динамику, а не как оценку.

### `parent_verified`

```json
{
  "id": "psy-week01-home-01",
  "type": "parent_verified",
  "stem": "Расскажи родителю о своей «суперсиле» — сильной черте характера.",
  "verificationPrompt": "Ребёнок назвал свою сильную сторону и объяснил выбор?",
  "credits": 5,
  "cooldownHours": 168
}
```

## 5. Валидация и публикация

```bash
# проверить один пакет
node packages/content-tools/bin/validate.js content/packs/<id>

# проверить все (запускается в CI на каждый PR)
node packages/content-tools/bin/validate.js content/packs/*
```

Валидатор проверяет:
1. Соответствие JSON Schema (`task-pack.schema.json`, `task-item.schema.json`).
2. Уникальность `id` заданий внутри пакета и глобально по репозиторию.
3. Что каждый файл из `items[]` существует, и наоборот — что нет «сирот» в `items/`.
4. Что у оцениваемых типов есть корректный `answer`, а у `single_choice` ровно один верный.
5. Что `dailyCreditCap` задан и разумен (предупреждение при > 100).
6. Что все ссылки на `assets/` разрешаются.

**Публикация** добавляет `pack.sig` — подпись приватным ключом семьи. Агент отвергает
пакеты без валидной подписи. Это закрывает очевидный вектор: подложить свой пакет
с `creditsPerCorrect: 9999`.

## 6. Как добавить новый предмет — чеклист

1. `mkdir content/packs/ru.mykids.<subject>.<topic>`
2. Написать `pack.json`, взяв за основу существующий.
3. Добавить задания в `items/`, каждое — отдельный файл (удобно для code review и git diff).
4. `node packages/content-tools/bin/validate.js content/packs/<id>` — зелёный.
5. PR. CI прогоняет валидатор.
6. После мержа — загрузка через админку или `git pull` на сервере, затем назначение
   ребёнку в разделе «Контент».

Пересборка агентов не требуется.

## 7. Импорт извне (фаза 4)

| Источник | Инструмент |
|---|---|
| Moodle GIFT | `content-tools/import/gift.ts` — самый простой массовый импорт |
| Moodle XML | `content-tools/import/moodle-xml.ts` |
| QTI 3.0 | `content-tools/import/qti.ts` — доступ к банкам заданий издателей |
| CSV | Для быстрой заливки таблиц из Excel |

Плюс **генераторы**: для математики и физики параметризованный шаблон
(«найти силу при m ∈ [1..10], a ∈ [1..10]») даёт сотни заданий из одного описания и
решает проблему исчерпания банка.
