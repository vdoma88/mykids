# MyKids

Система контроля экранного времени для Windows и Android, в которой ребёнок зарабатывает
экранное время учебными заданиями и тестами.

**Статус: работает на Windows.** Сервер, админка, интерфейс ребёнка, задания и
Windows-агент со службой — на месте. Android-агента пока нет.

**Ставится по [`docs/SETUP.md`](docs/SETUP.md)** — с нуля до закрывающегося
экрана примерно полчаса.

## Идея

- Экранное время расходуется из дневного лимита.
- Ребёнок решает задания и тесты → получает **кредиты**.
- Кредиты конвертируются в **минуты** (с потолком, чтобы нельзя было нафармить весь день)
  или тратятся во внутреннем магазине на другие награды.
- Родитель управляет всем через веб-админку.
- Задания добавляются пакетами-данными, без пересборки приложений — от психологии до
  физики, химии и информатики.

## Сервер

```bash
cp deploy/.env.example deploy/.env      # и смените пароль с секретом
docker compose -f deploy/docker-compose.yml up -d
```

Источник истины по балансам и политикам ([`server/api`](server/api/README.md)).
Без него раннер и агент считают кредиты локально, а такие данные ребёнок может
отредактировать. Данные об активности остаются на вашей машине.

Родитель открывает `http://адрес-сервера:3000/`, ребёнок — тот же адрес с
`/child`. Отдельного сервера для интерфейса нет: страницы отдаёт сам API.

## Админка и интерфейс ребёнка

```bash
npm run dev:admin    # разработка: http://localhost:5174
```

Родитель управляет детьми, политиками, магазином и журналом; ребёнок видит свой
баланс и — намеренно — свои правила ([`server/admin-ui`](server/admin-ui/README.md)).

## Доменное ядро

```bash
npm install
npm test        # 49 тестов
npm run typecheck
```

Правила системы — экономика, ledger, расписание — живут чистыми функциями в
[`packages/domain`](packages/domain/README.md), без базы и сети. Там же описаны решения,
которые легко сломать обратно: направление счёта при обмене, источник времени для
суточных лимитов, поведение ночного окна на границе дней.

## Агент для Windows

```bash
cd agents/windows && ./build.sh   # dist/mykids-agent.exe
go test ./...
```

Считает экранное время и закрывает экран по расписанию и лимиту
([`agents/windows`](agents/windows/README.md)). В бою это два процесса: служба
под `LocalSystem`, которую ребёнок остановить не может, и помощник в его
сессии, которого служба поднимает сама.

Ядро покрыто тестами и проверяется живым запуском двух процессов; Win32-часть
собирается и проходит `vet`, но на настоящей Windows ещё не запускалась.
Поэтому у агента остались и одиночные режимы — `status`, `watch`, `run`, —
чтобы проверять его постепенно.

Установка: [`docs/SETUP.md`](docs/SETUP.md).

## Раннер заданий

```bash
npm run dev:runner   # http://localhost:5173
```

Веб-раннер ([`packages/task-runner`](packages/task-runner/README.md)) рендерит все
типы заданий и считает кредиты через доменные функции. Отдельная страница для
локального прогона; у ребёнка он живёт внутри интерфейса на `/child`.

## Пакеты заданий

```bash
npm install
npm run validate
```

14 пакетов, 84 задания: 12 недель программы UKids, набор дополнительных навыков и
эталонный пакет по механике.

Валидатор проверяет пакеты по JSON Schema плюс правила, которые схемой не выражаются:
уникальность идентификаторов, корректность правильных ответов, наличие антифарм-лимитов.
Запускается в CI на каждый pull request.

Как добавить свой предмет — см. чеклист в
[`docs/content-format/README.md`](docs/content-format/README.md#6-как-добавить-новый-предмет--чеклист).

## Наследие

`legacy/ukids-app.html` — работающий прототип 12-недельной программы развития soft skills
(UKids Home). Открывается двойным кликом в браузере, прогресс хранится в `localStorage`.

Его контент — источник психологических пакетов заданий. Пакеты **генерируются**, а не
правятся вручную:

```bash
npm run import:ukids   # перечитать legacy/ukids-app.html → content/packs/
npm run test:legacy    # дымовой тест прототипа (нужен Chromium)
```

CI следит, чтобы `content/` не расходился с источником: правка сгенерированного пакета
руками будет затёрта следующим импортом, поэтому такая правка валит сборку.

Интерактивные упражнения прототипа (таблица Шульте, матрица Эйзенхауэра, дыхание 4-7-8
и другие) в целевой системе становятся виджетами типа `interactive`.
