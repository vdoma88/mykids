# Целевая архитектура MyKids

Система контроля экранного времени для Windows и Android, где ребёнок зарабатывает
экранное время через учебные задания и тесты.

---

## 1. Общая картина

```
                    ┌──────────────────────────────────┐
                    │  Сервер семьи (self-hosted)      │
                    │                                  │
                    │  ├── API (REST + WebSocket)      │
                    │  ├── Ledger (журнал операций)    │
                    │  ├── Content registry (пакеты)   │
                    │  ├── Policy engine               │
                    │  └── Админка (SPA)   ◄───── родитель, браузер
                    └───────────┬──────────────────────┘
                                │  HTTPS, offline-first sync
                ┌───────────────┴────────────────┐
                │                                │
    ┌───────────▼───────────┐      ┌─────────────▼─────────────┐
    │  Windows-агент        │      │  Android-агент            │
    │                       │      │                           │
    │  Служба (LocalSystem) │      │  Foreground Service       │
    │   ├ трекинг           │      │   ├ UsageStatsManager     │
    │   ├ enforcement       │      │   ├ overlay-блокировка    │
    │   └ локальный SQLite  │      │   └ локальный SQLite      │
    │         ▲ named pipe  │      │         ▲                 │
    │  UI в сессии юзера    │      │  Activity (Compose)       │
    │   ├ оверлей блокировки│      │   ├ оверлей блокировки    │
    │   ├ магазин           │      │   ├ магазин               │
    │   └ WebView2 ─────────┼──┐   │   └ WebView ──────────┐   │
    └───────────────────────┘  │   └───────────────────────┼───┘
                               │                           │
                        ┌──────▼───────────────────────────▼──┐
                        │   Task Runner (веб, один на всех)   │
                        │   рендерит пакеты заданий           │
                        └─────────────────────────────────────┘
```

**Ключевое решение:** учебный модуль — это веб-приложение, встроенное через WebView. Один
рендерер работает на Windows, Android и в браузере админки для предпросмотра. Новые задания
не требуют пересборки агентов.

## 2. Выбор стека

| Компонент | Технология | Почему |
|---|---|---|
| Бэкенд | **TypeScript / NestJS + PostgreSQL** | Общие типы с админкой и Task Runner через один пакет `@mykids/contracts` |
| Админка | **React + TanStack Query + Vite** | |
| Task Runner | **TypeScript, без фреймворка или Preact** | Должен быть лёгким — крутится в WebView на слабом телефоне |
| Windows-агент | **Go** (изначально планировался C# / .NET 8) | Один статический `.exe` без установки рантайма на компьютер ребёнка; кросс-сборка из Linux, поэтому агент собирается в CI. Минус — оверлей пишется на голых вызовах user32 |
| Android-агент | **Kotlin + Jetpack Compose** | Единственный вменяемый путь к системным API |
| Локальное хранилище агентов | **SQLite** | |

### Почему не единый кроссплатформенный фреймворк

Рассматривали .NET MAUI и Flutter ради одного языка. Отвергнуто: enforcement на каждой
платформе всё равно пишется нативно (Win32 API / `DevicePolicyManager`), то есть 80%
сложного кода кроссплатформенность не покрывает. А UI агента — это 5-6 экранов, экономия
на них не окупает потерю прямого доступа к системе и осложнения с фоновыми сервисами.

Кроссплатформенность мы получаем там, где она реально даёт выигрыш — в контенте, через
WebView.

## 3. Доменная модель

### Две валюты — это принципиально

| | Кредиты | Минуты |
|---|---|---|
| Откуда | Задания, тесты, подтверждённые родителем дела | Дневной лимит + конвертация + покупки |
| Куда | Магазин, конвертация в минуты | Расходуются экраном |
| Копятся | Да, без ограничения | Да, но с потолком переноса на завтра |

Разделение нужно, чтобы:
1. в магазине были **не только минуты** (поход в кино, выбор фильма на вечер, отложенный отбой);
2. курс обмена и дневной потолок конвертации регулировались независимо от заработка.

> Без потолка конвертации ребёнок решает 200 однотипных примеров и играет весь день.
> `maxConvertedMinutesPerDay` — обязательный параметр, не опция.

### Сущности

```
Family
 ├── Guardian (родитель; роли: owner | parent | viewer)
 └── Child
      ├── Device (platform: windows|android, deviceId, lastSeenAt, agentVersion)
      ├── TimeAccount  ─── дневной лимит, перенос, текущий баланс
      ├── CreditAccount
      ├── Policy       ─── расписание, категории приложений, bedtime
      ├── Assignment   ─── какие пакеты заданий назначены
      └── Attempt      ─── попытки прохождения заданий
```

### Ledger — единственный источник истины

Балансы **не хранятся как изменяемое поле**. Баланс = свёртка append-only журнала:

```
LedgerEntry {
  id            uuid
  childId       uuid
  currency      'minutes' | 'credits'
  amount        int          // со знаком
  reason        'daily_grant' | 'task_reward' | 'conversion' | 'purchase'
                | 'screen_usage' | 'manual_adjust' | 'tamper_penalty'
  refType/refId ссылка на источник (attempt, purchase, usage_session…)
  deviceId      где произошло
  occurredAt    время устройства
  recordedAt    время сервера
  seq           монотонный счётчик на устройство
}
```

Это даёт: аудит («почему у него сегодня 40 минут?»), корректный офлайн-синк без гонок,
разбор конфликтов и возможность отката ошибочного начисления без пересчёта состояния.

## 4. Синхронизация и античит

Агенты работают **offline-first**: связь с сервером может пропасть, ребёнок не должен
получить ни бесконечное время, ни полную блокировку.

### Правило асимметрии

| Операция | Офлайн |
|---|---|
| **Списание** минут за использование экрана | **Разрешено.** Иначе отключение Wi-Fi = бесконечное время |
| **Начисление** минут за задания | **Только с подтверждением сервера.** Иначе тривиальный чит |
| Покупка в магазине | Разрешена из уже накопленного баланса, синкается позже |
| Выдача дневного лимита | Разрешена, но не более чем за 1 день вперёд |

### Защита от подкрутки часов

- Каждая запись несёт `occurredAt` (часы устройства) и `recordedAt` (часы сервера).
- Агент хранит монотонный счётчик (`SystemClock.elapsedRealtime` / `QueryPerformanceCounter`).
  Если системное время прыгнуло, а монотонное — нет, это подкрутка → событие `tamper`.
- Расхождение с сервером > 5 минут при наличии связи → принудительная синхронизация времени.

### Защита от подмены контента

Пакеты заданий подписываются (Ed25519). Агент не принимает пакет без валидной подписи
семьи. Без этого ребёнок подкладывает свой пакет с `creditsPerCorrect: 9999` — вектор
очевидный и обязательный к закрытию.

### Tamper-события

Служба остановлена, приложение удалено из автозапуска, отозвано разрешение Usage Access,
устройство молчит дольше N часов — всё это пишется в журнал и уходит родителю. Политика
реакции настраивается: от уведомления до `tamper_penalty` (списание минут).

## 5. Windows-агент

### Два процесса

**Служба (LocalSystem, автозапуск)** — делает всё важное:
- Трекинг активного окна: `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` +
  `QueryFullProcessImageName` для пути к exe.
- Простой (idle): `GetLastInputInfo`. Время без ввода не списывается.
- События сессии: `WTSRegisterSessionNotification` — блокировка, разблокировка, вход, выход.
- Enforcement: завершение или заморозка (`NtSuspendProcess`) процессов из чёрного списка,
  сигнал UI на показ оверлея.
- Локальный SQLite + очередь синхронизации.

**UI в сессии пользователя (обычные права)**:
- Полноэкранный оверлей блокировки (topmost, без кнопки закрытия, поверх панели задач).
- Магазин, баланс, задания (WebView2).
- Трей-иконка со счётчиком остатка.

Связь — named pipe с проверкой SID вызывающего.

### Обязательное условие

**Ребёнок работает под обычной учётной записью, без прав администратора.** Это не
рекомендация, а условие работоспособности: локальный админ останавливает службу штатными
средствами.

### Взаимный watchdog

Служба перезапускает UI, если тот умер. UI пингует службу; если служба не отвечает — экран
блокируется, а факт пишется в журнал как tamper. Пропуск времени между остановкой и
запуском службы засчитывается как использованное время.

## 6. Android-агент

### Профили развёртывания

**Профиль A — «мягкий»** (обычная установка, ребёнок сотрудничает):
- `PACKAGE_USAGE_STATS` — учёт использования приложений
- `SYSTEM_ALERT_WINDOW` — оверлей блокировки
- `FOREGROUND_SERVICE` + `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`
- Device Admin — защита от удаления
- `MediaSessionManager` — пауза видео и музыки при блокировке

Обходится: безопасный режим, второй пользователь, ADB. Годится, когда есть договорённость.

**Профиль B — «жёсткий»** (Device Owner):
- Провижининг QR-кодом на устройстве после сброса к заводским настройкам (Android 9+)
- `setPackagesSuspended()` — приложение реально не запускается, а не закрывается оверлеем
- `setUninstallBlocked()`, `setApplicationHidden()`
- Lock task mode (COSU) для «учебного режима»
- Запрет добавления пользователей и безопасного режима через `UserManager` restrictions

Не обходится штатными средствами. Цена — сброс устройства при подключении.

### Чего не делаем

**Не строим enforcement на AccessibilityService.** Причины — в `PRIOR-ART.md` §7: политика
Play и автоматический отзыв доступа в Android 17 при Advanced Protection Mode. Это выглядит
как самый простой путь и является самым коротким путём к неработающему продукту.

## 7. Политики (Policy Engine)

Считается на сервере, кэшируется на устройстве, применяется локально.

```yaml
dailyLimits:            # минут в день
  mon-thu: 60
  fri: 90
  sat-sun: 120
carryOverMaxMinutes: 30 # сколько неистраченного переносится на завтра

windows:
  school:   { days: mon-fri, from: "08:00", to: "14:00", mode: blocked }
  bedtime:  { from: "21:30", to: "07:00", mode: blocked }
  homework: { days: mon-fri, from: "16:00", to: "18:00", mode: tasks_only }

appCategories:
  always_allowed: [phone, messages, clock, mykids]  # не считаются и не блокируются
  metered:        [games, video, social]            # считаются, блокируются
  educational:    [dictionary, calculator]          # считаются, но не блокируются
  blocked:        []                                # запрещены всегда

economy:
  creditsPerMinute: 2           # курс обмена
  maxConvertedMinutesPerDay: 45 # потолок конвертации — антифарм
  minCreditsToConvert: 10
```

Важная деталь: категория `always_allowed` обязана существовать. Ребёнок должен иметь
возможность позвонить родителю при нулевом балансе.

## 8. Магазин

`StoreItem`:
```
id, title, description, icon
cost: { currency: 'credits'|'minutes', amount }
effect:
  - grant_minutes(30)            # +30 минут сегодня
  - unlock_app(packageId, 60)    # разблокировать конкретное приложение на час
  - shift_bedtime(30)            # отодвинуть отбой
  - weekend_pass                 # день без лимита
  - custom                       # офлайн-награда, исполняет родитель
constraints:
  maxPerDay / maxPerWeek
  cooldownHours
  requiresApproval: bool
  availableWindows: [...]        # нельзя купить время в школьные часы
  minAgeYears
```

Родитель заводит собственные товары через админку — это делает систему живой, потому что
самые мотивирующие награды у каждой семьи свои.

## 9. Безопасность и приватность

- **Self-hosted по умолчанию.** Данные об активности ребёнка не уходят в чужое облако.
  Docker Compose: API + PostgreSQL + reverse proxy.
- Родительская аутентификация — пароль + TOTP. Никаких PIN по умолчанию в коде.
- Агент аутентифицируется device-токеном, выданным при привязке; токен ротируется.
- Шифрование локальной БД агента, ключ в DPAPI (Windows) / Keystore (Android).
- Не собираем содержимое экрана, переписку и нажатия клавиш. Только: имя приложения,
  длительность, результаты заданий. Это осознанная граница.

> **Педагогическое замечание, важное для архитектуры.** Правила и журнал должны быть видны
> ребёнку в его интерфейсе. Скрытая слежка за подростком 11-13 лет всё равно вскрывается,
> и тогда рушится не только система контроля, но и доверие. Проектируем прозрачный
> «договор», а не тайный надзор — поэтому у ребёнка есть свой экран баланса и истории.
