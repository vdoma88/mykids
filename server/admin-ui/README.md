# @mykids/admin-ui

Интерфейс родителя и интерфейс ребёнка — одна сборка, два раздела.

```bash
npm run dev:admin        # http://localhost:5174, API проксируется на :3000
npm run build -w @mykids/admin-ui
node server/admin-ui/e2e.mjs   # сквозной тест в Chromium
```

В бою сборка отдаётся самим API с того же адреса: родитель открывает
`http://адрес-сервера:3000/`, ребёнок — `/child`. Два адреса вместо одного —
это ровно та инструкция, на которой домашнее развёртывание и заканчивается.
Путь к собранной сборке сервер берёт относительно себя; переопределяется
`MYKIDS_WEB_ROOT`. Порт 5174 остаётся только для разработки, где нужен
горячий перезапуск.

## Разделы

| Путь | Доступ | Что там |
|---|---|---|
| `/children` | сессия родителя | Балансы, устройства, статус агентов |
| `/children/:id` | сессия родителя | Политика, симулятор курса, журнал, корректировка, выдача токена |
| `/store` | сессия родителя | Товары магазина |
| `/approvals` | сессия родителя | Очередь покупок и заданий на подтверждение |
| `/child` | токен устройства | Задания, баланс, правила, обмен, магазин |

## Решения

**Задания решаются в браузере, а кредиты назначает сервер.** Правильные ответы
всё равно попадают на устройство ребёнка — иначе задание там не проверить.
Поэтому сервер ограничивает не честность ответа, а суммы: дневной потолок
пакета, общий дневной потолок и cooldown на повтор задания. Обойти проверку
ответа можно; получить больше дневного потолка — нельзя. Это принятая цена, а
не недосмотр; антифарм по времени ответа — в `docs/ROADMAP.md`, фаза 5.

**Пакеты берутся тем же загрузчиком, что и на странице локального прогона.**
Свой формат выдачи означал бы два загрузчика, а они разъезжаются молча.

**Симулятор курса на странице ребёнка.** Курс обмена невозможно настроить
наугад — нужно видеть, во что превращается дневной заработок. Считает теми же
функциями `@mykids/domain`, что и сервер, поэтому цифра на экране и начисление в
журнале не разойдутся.

**Ребёнку показываются его правила, а не только баланс.** Лимит на сегодня, курс,
потолки, расписание. Скрытая механика в 11-13 лет воспринимается как
несправедливость и провоцирует искать обход вместо игры по правилам.

**Сообщение о результате строится по ответу сервера.** Обмен урезается до
доступного, и обещать больше выданного нельзя: запросил 100 минут, получил 10 —
интерфейс обязан сказать именно это.

**Токен родителя и токен устройства хранятся раздельно.** Админка и интерфейс
ребёнка могут быть открыты на одной машине, путать их доступы нельзя.

**Запрос не уходит, пока нечем авторизоваться.** Иначе первый 401 прилетает
раньше, чем ребёнок успел ввести токен, и стирает только что введённое.

**Просроченный токен сверяется по коду ответа, а не по тексту ошибки.** Текст
меняется, код — нет.

## Что проверяет сквозной тест

Поднимает API и собранную статику, затем проходит оба пути целиком: регистрация
семьи, добавление ребёнка, симулятор, правка и перечитывание политики,
корректировка баланса с причиной, выдача токена, товар в магазине — и со стороны
ребёнка: баланс, правила, обмен, покупка, урезанный обмен, отказ при нулевом
балансе.

Он ловит то, чего не видят юнит-тесты: что фронт и API действительно
договариваются. Три бага из этого раздела найдены именно им.
