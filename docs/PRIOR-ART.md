## 1. Ближайший аналог: Child Screen Time (CST)

**https://github.com/childscreentime/cst** · MIT · Java · minSdk 28 (Android 9)

Самый близкий к нашей задаче проект. Уже реализует то, что мы собирались писать сами:

| Возможность CST | Наша потребность |
|---|---|
| Учёт экранного времени с точностью до минуты через `UsageStatsManager` | да, ядро трекинга |
| Неотключаемый полноэкранный оверлей при исчерпании лимита (`SYSTEM_ALERT_WINDOW`) | да, enforcement |
| **Кредитная модель продления времени** (продления по 1 и 5 минут) | да, но нам нужна связка с заданиями |
| Foreground Service + WorkManager, переживает убийство системой | да |
| Device Administrator для защиты от удаления | да |
| Media Session Listener — ставит на паузу видео/игры/музыку при блокировке | да, важная деталь UX |
| Локальная админка под PIN (по умолчанию `3443`) | заменяем на нашу серверную |
| CI: GitHub Actions → GitHub Releases + Amazon Appstore | да, готовый конвейер сборки |

**Чего в CST нет:** сервера, синхронизации между устройствами, Windows, заданий/тестов,
магазина, аналитики.

**Вывод:** MIT-лицензия позволяет взять CST как основу Android-агента. Экономия — примерно
месяц работы на самой рискованной части (enforcement + выживание сервиса). Наша работа
сводится к добавлению сетевого слоя, ledger-синхронизации и модуля заданий.

> Осторожно: PIN по умолчанию `3443` и локальное хранение настроек в SharedPreferences —
> это надо переделывать в первую очередь, иначе обходится за минуту.

## 4. Трекинг как отдельная задача

**[ActivityWatch](https://github.com/ActivityWatch/activitywatch)** (MPL-2.0) — самый зрелый
открытый кроссплатформенный трекер: Windows, macOS, Linux, Android.

Архитектура прямо ложится на нашу: локальный сервер с REST API + отдельные «watchers»,
которые репортят события. Есть `aw-server-rust`, клиентские библиотеки на Python/JS/Rust.

**Как использовать:** не как зависимость (тянет свой сервер и UI), а как референс модели
данных временных рядов — `bucket → event {timestamp, duration, data}` и языка запросов к
ним. Наш `usage_event` спроектирован по этому образцу.

## 5. Связка «учёба → экранное время»

**Quiznoob** ([сервер](https://github.com/johncallahan/quiznoob),
[Flutter-клиент](https://github.com/johncallahan/quiznoob-flutter)) — единственный найденный
открытый проект с ровно нашей идеей: ребёнок решает квиз и получает интернет-время. Время
выдаётся через webhook IFTTT в роутер Circle.

**Что берём:** подтверждение идеи и урок из его ограничений — привязка к конкретному
роутеру делает решение неприменимым вне дома и не покрывает офлайн-игры на ПК. Мы считаем
время на самом устройстве, а не на сетевом периметре.

**Что не берём:** банк вопросов в виде Excel-файлов. Это ровно та ошибка, от которой нас
спасает формализованный формат пакетов (см. `docs/content-format/README.md`).

## 6. Стандарты для банка заданий

| Стандарт | Вердикт |
|---|---|
| **[QTI 3.0](https://www.1edtech.org/standards/qti)** (1EdTech, май 2022) — XML-формат обмена тестовыми заданиями между LMS | Не берём как внутренний формат: избыточно тяжёлый для наших нужд. Но **поддерживаем импорт** — это открывает доступ к готовым банкам заданий от издателей. |
| **Moodle GIFT / XML** | Самый простой путь массового импорта задач. Импортёр — фаза 4. |
| **H5P** | Интересен как источник интерактивных типов, но тянет свой рантайм. Отложено. |
| **xAPI (Tin Can)** | Хорош для журнала попыток, если понадобится отдавать данные во внешнюю LMS. Не для MVP. |

**Решение:** внутренний формат — свой, компактный, JSON, с JSON Schema и валидатором в CI.
QTI/GIFT — только на границе, через импортёры.

## 7. Регуляторные ограничения (проверено на сентябрь 2026)

Это не мелочь — от этого зависит выбор технологии enforcement.

### AccessibilityService на Android — тупик

- [Политика Google Play](https://support.google.com/googleplay/android-developer/answer/10964491)
  запрещает использовать Accessibility API, чтобы «не давать пользователю отключить или
  удалить приложение».
- В Android 17 (Beta 2) при включённом **Advanced Protection Mode** система автоматически
  отзывает доступ к AccessibilityService у приложений, не объявленных как настоящие
  вспомогательные средства (`isAccessibilityTool`).

**Следствие:** архитектуру нельзя строить на Accessibility. Основа — `UsageStatsManager`
плюс, где возможно, `DevicePolicyManager` в роли Device Owner.

### Прочие требования Play

- `QUERY_ALL_PACKAGES` — только по декларации в Play Console, для «core functionality».
- `VpnService` разрешён для родительского контроля, но требует обоснования.
- Device Admin API постепенно урезается в пользу Android Enterprise.

**Следствие для дистрибуции:** первый релиз — прямая установка APK и/или F-Droid. Публикация
в Play — отдельная задача с декларациями, не блокирующая разработку.

### Windows

Ограничений магазина нет — распространяем подписанный MSI/MSIX напрямую. Но есть жёсткое
архитектурное требование: **у ребёнка должна быть обычная учётная запись без прав
администратора**. Локальный админ отключает службу за 10 секунд, и никакая изобретательность
это не компенсирует.
