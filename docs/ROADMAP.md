# Дорожная карта

Оценки — в человеко-неделях для одного разработчика, работающего полный день.
Суммарно до полноценного MVP на двух платформах — **порядка 4-5 месяцев**.
Это надо принять на входе: проект такого объёма нельзя «сделать за пару вечеров».

---

**Критерий готовности:** `git clone` + `npm run validate` проходят на чистой машине.

## Фаза 1 — Ядро без блокировки · 3-4 недели

> Взят Fastify вместо NestJS: монорепа на строгом ESM, а декораторы NestJS
> тянут CommonJS и отдельный tsconfig. Обоснование — в `server/api/README.md`.

Работающая экономика, но время выдаёт родитель вручную.

- [x] Доменное ядро: ledger, экономика, политики, окна расписания — чистые функции
      с 49 тестами (`packages/domain`)
- [x] Контракты: типы и zod-схемы домена (`packages/contracts`)
- [x] Персистентность: PostgreSQL, Prisma, миграции
- [x] REST API поверх домена, аутентификация родителя (пароль + TOTP), токены устройств
- [x] Админка: дети, политики, экономика, магазин, журнал, одобрения
- [x] Task Runner: движок проверки, движок сессии, DOM-рендереры всех типов,
      виджеты `schulte` и `breathing`, страница для локального прогона
- [x] Интерфейс ребёнка в браузере: задания, баланс, правила, обмен, магазин
- [x] Docker Compose для развёртывания дома; сервер отдаёт интерфейс и
      пакеты заданий с того же адреса, что и API
- [x] Очередь одобрений разбирается: задания подтверждаются, покупки
      одобряются или отклоняются с возвратом цены
- [x] Интерфейс на уровне телефона: адаптивная раскладка, тёмная тема,
      вкладки у страницы ребёнка, настройки со вторым фактором, отвязка
      устройств, часовой пояс семьи

> **Здесь главный смысл фазы.** Прежде чем вкладываться в системное программирование под
> две платформы, надо проверить на живом ребёнке, что механика мотивирует: не слишком ли
> легко фармятся кредиты, адекватен ли курс, интересны ли задания. Ошибка в экономике,
> обнаруженная после написания Windows-службы, стоит месяца.

**Критерий готовности:** две недели реального использования вручную; курс обмена не
переписывался последние 3 дня.

## Фаза 2 — Windows-агент · 4-6 недель

> Взят Go вместо C#/.NET: один статический `.exe` без установки рантайма на
> компьютер ребёнка и кросс-сборка из CI. Обоснование — в `agents/windows/README.md`.

- [x] Ядро агента: расписание, учёт с простоем, состояние на диске — 30 тестов,
      идут на любой ОС (`agents/windows`)
- [x] Win32-слой: активное окно, простой, блокировка экрана, полноэкранный оверлей
- [x] Кросс-сборка `.exe` из Linux, артефакт в CI
- [x] Клиент сервера в агенте: `/agent/sync`, `/agent/usage`, `/agent/tamper`
- [x] Очередь расхода на диске (`outbox.jsonl`), переживающая офлайн и перезапуск
- [x] Политика с сервера и кэш для офлайна: правка `policy.json` ребёнком ничего не даёт
- [x] Детект подкрутки системных часов с компенсацией сдвига
- [x] Проверка агента против настоящего API, а не против фальшивого сервера (`integration.sh`)
- [x] Снятие агента фиксируется и оплачивается: пропущенное время списывается,
      родитель видит событие даже если сеть отключали
- [x] Протокол службы и помощника: наблюдения от помощника, решения от службы;
      молчание помощника считается расходом, а не отдыхом
- [x] Windows Service (LocalSystem): установка, автозапуск, перезапуск после
      сбоя, события сессии; наблюдение вынесено в помощника
- [x] Ловля лжи помощника о простое: без ввода активное окно не переключается,
      и противоречие видно службе без всякого Win32
- [x] Окно проверки Win32-слоя на живой машине без командной строки
      (`mykids-check.exe`): решения в `internal/selftest` и покрыты тестами
- [x] Встречная проверка сессии средствами WTS: второй источник для блокировки
      экрана, независимый от помощника. Ответ диспетчера сессий главнее слова
      помощника в обе стороны, и принимается даже когда помощник молчит
- [x] Экран для подростка: предупреждение заранее, причина, остаток кредитов,
      что будет завтра и куда идти за временем; текст готовит служба, помощник
      только рисует
- [x] Значок в трее: остаток времени виден всегда, оттуда же открываются
      задания. До него агент был невидим до самого закрытого экрана
- [x] Браузер в белом списке, чтобы задания открывались с закрытого экрана,
      а не только с другого устройства
- [ ] Магазин и задания в самом агенте, в WebView2. Отложено осознанно: нужен
      установленный WebView2 Runtime и COM-обвязка из Go, проверить которую
      негде, а браузер из белого списка ту же задачу уже решает
- [x] Канал службы и помощника ограничен списком доступа: писать в него может
      только интерактивный пользователь, а доверия к помощнику всё равно нет
- [x] Служба сама поднимает помощника в сессии ребёнка и следит за ним;
      пять перезапусков за десять минут считаются снятием наблюдателя, и
      родитель получает событие
- [x] Установка без командной строки: окно с тремя полями (`mykids-setup.exe`),
      проверка введённого до того, как что-то тронуто
- [x] MSI-инсталлятор: запись в «Программах и компонентах», ярлыки в меню
      «Пуск», обновление поверх и — главное — снятие службы при удалении.
      Собирается wixl на любой ОС (`deploy/build-msi.sh`)
- [ ] Подпись кода и автообновление. Подпись упирается в сертификат, который
      надо покупать; без неё SmartScreen будет ругаться
- [x] Установка одним скриптом: проверка прав учётной записи ребёнка, каталог
      данных, привязка, регистрация службы (`deploy/install-windows.ps1`,
      `docs/SETUP.md`)

**Критерий готовности:** ребёнок не может продлить время без кредитов; попытка остановить
службу фиксируется в журнале.

## Фаза 5 — Закалка · постоянно

- [x] Антифарм, детект слишком быстрых ответов: промежутки между приходами
      попыток штампует сервер, и подделать их нельзя, не замедлившись на самом
      деле. Одна быстрая попытка не в счёт — быстро отвечает и тот, кто знает
- [x] Убывающие кредиты за повторы: второе решение того же задания за месяц
      стоит половины, третье — четверти, и дальше не падает. Возврат после
      месячного перерыва снова полон: это самое полезное повторение, и
      наказывать за него было бы наоборот
- [x] Сервер сам проверяет ответ и сам называет цену: `/child/attempts`
      принимает только сам ответ, а правильный ответ, цену задания, потолок
      пакета и cooldown читает из своего экземпляра пакета. До этого их
      присылал браузер ребёнка — то есть весь антифарм обходился одним
      запросом мимо страницы
- [x] Задания, которые проверить машиной нельзя (`parent_verified`, больше
      половины всех), не платят за нажатие кнопки: попытка встаёт в очередь,
      и кредиты назначаются при подтверждении родителем — по цене из пакета
      и сегодняшним потолкам
- [ ] Антифарм дальше: интервальное повторение (FSRS) — подача заданий тогда,
      когда их пора вспомнить, а не когда кончился cooldown
- [ ] Адаптивная подача заданий по сложности
- [ ] Антитамперинг: реакция на отзыв разрешений, безопасный режим, второго пользователя
- [ ] Тип задания `code` с песочницей
- [ ] Резервное копирование и восстановление, миграции данных
- [ ] Публикация в Google Play с декларациями разрешений (не блокирует остальное)

## Риски

| Риск | Оценка | Что делаем |
|---|---|---|
| **Ребёнок обходит блокировку** | Высокая вероятность | Windows: обычная учётка обязательна. Android: Device Owner, если нужна гарантия. Принять, что профиль A обходится |
| **Google Play отклонит приложение** | Средняя | Дистрибуция APK напрямую с первого дня; Play — опционально, в фазе 5 |
| **Android 17 ужесточает Accessibility** | Уже происходит | Не строим enforcement на Accessibility вообще (см. `PRIOR-ART.md` §7) |
| **Перекос экономики, фарм лёгких заданий** | Высокая | `dailyCreditCap` на пакет, потолок конвертации, cooldown, симулятор в админке |
| **Подмена контента ребёнком** | Средняя | Обязательная подпись пакетов Ed25519 |
| **Объём работ недооценён** | Высокая | Фаза 1 даёт полезный продукт без агентов. Если проект остановится там — он уже работает |
| **Конфликт с ребёнком, гонка вооружений** | Высокая | Прозрачные правила, видимый журнал, договорённость. Скрытая слежка в 11-13 лет разрушает доверие и всё равно вскрывается |

## Что делать прямо сейчас

1. Согласовать формат Task Pack — он определяет всё остальное (`docs/content-format/README.md`).
2. Закрыть фазу 0: репозиторий должен нормально клонироваться.
3. Начать фазу 1 с бэкенда и ledger — это фундамент, который потом не переписывается.
