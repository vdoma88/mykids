# @mykids/task-runner

Веб-раннер заданий: один рендерер на все платформы. На Windows и Android он
крутится в WebView, в админке — в предпросмотре, локально — отдельной страницей.

```bash
npm run dev:runner        # сборка + сервер на http://localhost:5173
npm run build -w @mykids/task-runner
node packages/task-runner/smoke-test.mjs
```

## Слои

| Модуль | Отвечает за |
|---|---|
| `grade.ts` | Проверка ответа. Чистая функция, без сети и времени |
| `session.ts` | Ход сессии, отбор заданий, подсчёт кредитов через `@mykids/domain` |
| `load.ts` | Загрузка пакетов по HTTP с проверкой схемами |
| `ui/render.ts` | DOM-рендереры типов заданий |
| `widgets/` | Интерактивные упражнения |

## Решения

**Кредиты здесь только считаются, а не начисляются.** Раннер работает на
устройстве ребёнка, и доверять его арифметике нельзя. Записывать начисления
будет сервер, пересчитывая теми же функциями домена.

**Начисление не завязано на `Grade.complete`.** У оцениваемых типов это поле
означает «верно полностью», поэтому частичный зачёт при нём даёт часть кредитов.
Решает `TaskSession.computeAward`.

**Regex в `short_text` компилируется с флагом `u`.** Без него `\w` не покрывает
кириллицу, и «^мо\w+» не матчит «море». Авторам заданий на русском нужен `\p{L}` —
валидатор пакетов предупреждает о `\w`.

**Заглушка виджета не даёт отметить выполнение мгновенно.** Реализованы `schulte`
и `breathing`; остальные виджеты из перечня схемы отдаются заглушкой с таймером,
которая открывает кнопку только после `minDurationSec`. Иначе она стала бы
способом фармить кредиты в один клик.

**Порядок заданий не фиксирован.** При `selection: random` пакет выдаёт задания
вперемешку, поэтому и дымовой тест определяет тип задания по DOM, а не по номеру
шага.
